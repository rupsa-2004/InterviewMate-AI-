# InterviewMate AI – Presentation Script

> **Target duration:** 2–3 minutes
> **Format:** Live demo on laptop with browser open at http://localhost:5000
> **Preparation:** Run `python app.py` before starting; have the browser at the home page.

---

## Before You Begin — Setup Checklist

- [ ] Virtual environment activated: `.venv\Scripts\activate`
- [ ] Real IBM credentials filled in `.env`
- [ ] App running: `python app.py` (terminal minimised, not closed)
- [ ] Browser open at http://localhost:5000 — home page visible
- [ ] Browser zoom set to 100% or 110% for readability

## Technical Highlights (20 seconds)

> "Let me quickly highlight three technical aspects:
>
> First, the **RAG pipeline** — before every IBM Granite call, my code retrieves
> role-specific topics from a local JSON knowledge base using a keyword-scoring algorithm
> I wrote in pure Python. This gives the AI the right context without any vector database.
>
> Second, **responsible AI** — if IBM Granite is unavailable, the app raises a real error —
> it never substitutes fake scores. The evaluation notice is shown on every relevant page.
>
> Third, **automated testing** — 175 checks across two test suites verify the database,
> the RAG service, the prompt parser, Flask routes, and even the XSS escaping fix —
> all without needing real IBM credentials."

## Anticipated Questions and Answers

**Q: How is this different from just asking ChatGPT?**

> "InterviewMate AI is a structured practice environment — it tracks your sessions,
> scores you consistently, stores your history, and gives you six dimensions of feedback
> rather than a freeform response. The RAG knowledge base also grounds the questions
> in role-specific domain topics. And it uses IBM Granite, not ChatGPT."

**Q: What is RAG?**

> "RAG stands for Retrieval-Augmented Generation. Instead of letting the AI generate questions
> from scratch, I first retrieve relevant topics from a local JSON knowledge base using a
> keyword-scoring algorithm. Those topics are injected into the IBM Granite prompt,
> so the questions are grounded in real domain knowledge for that specific role."

**Q: What happens if IBM Cloud is down?**

> "The app shows a clear error message explaining that IBM watsonx.ai is unavailable.
> It never shows fake or hardcoded scores — if the API fails, the student sees the error
> and knows to try again."

**Q: Is the student's data safe?**

> "Yes. All session data is stored only in a local SQLite file on the student's own computer.
> Only the question text and the student's answer are sent to IBM watsonx.ai for evaluation —
> nothing else leaves the machine. API credentials are stored in a local `.env` file
> that is excluded from Git."

**Q: Why SQLite and not MySQL or PostgreSQL?**

> "For a college project running on a single laptop, SQLite is the right choice.
> There is no server to install or configure — the database is a single file.
> The code could be switched to PostgreSQL with minimal changes to `db.py`
> if deployment to a production server were required."

**Q: Did you test this?**

> "Yes — 175 automated checks in two test suites. The RAG and database suite tests all
> 8 data helpers and all 5 knowledge-base files. The integration suite mocks the IBM SDK
> and tests every Flask route, including credential detection, XSS escaping, and
> the full POST → redirect → results flow."
